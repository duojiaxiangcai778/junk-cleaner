# 2026-11-03 QQ / 微信 从「只看」改成「能清」

## 起因

用户发来快速清理页的截图，第一行是：

```
☑  QQ 数据            41.02 GB   不动   只看
```

原话：

> 这昨天写的清理软件，为什么 QQ 数据只看呢？我要你能清理呀！不清理，我让你把它加进去干啥？
> 就看着待着，就在这恶心我。顺便把微信也加进去，QQ、微信都是要能清理的

问题很清楚：v2.0.0 里这条是 `junk_items.py` 里写死的 `id="qq_data"`，`level="view"`，
路径硬编码 `D:\D\QQ数据`，界面上只能看不能勾。而且微信压根没进快速清理页。

## 排查：41 GB 到底是什么

先按目录拆了一遍（PowerShell 实测，2026-11-03 17:03）：

| 目录 | 大小 |
|---|---|
| `Tencent Files\1535693071`（主力账号） | 39.68 GB |
| └ `nt_data\Pic\*\Thumb`（**图片缩略图**） | **17.83 GB** |
| └ `nt_data\Pic\*\Ori`（原图） | 12.87 GB |
| └ `nt_data\Video` | 2.87 GB |
| └ `nt_data\Emoji`（`emoji-recv` 2.01 GB + `personal_emoji` 311 MB + 系统 255 MB） | 2.53 GB |
| └ `nt_db`（聊天文字数据库） | 1.96 GB |
| └ `nt_data\log` | 0.97 GB |
| └ `nt_temp` / `nt_data\File` / `Ptt` / `avatar` | 0.5 GB 左右 |
| `Tencent Files\nt_qq\global`（旧探测漏掉） | 0.29 GB |
| **`D:\D\QQ数据` 根目录散落文件**（96 个，视频/截图/安装包） | **1.03 GB** |
| 微信 `xwechat_files\wxid_...` | 326 MB（cache 78.8 / msg 174.7 / db_storage 50.2 / business 17.5） |

结论：**缩略图缓存一项就 17.83 GB**，2026-10 单月 7.74 GB、2026-09 单月 7.25 GB，
比原图还占地方。这些删了 QQ 会自己重建，完全可清 —— 以前却被打包成「不动」。

## 根因

1. `junk_items.py` 把整个 QQ 数据目录（`D:\D\QQ数据`）当**一项**、标 `view`，一刀切不动；
   实际上一个目录里混着三种东西（缓存 / 内容 / 数据库），必须拆开才能分档。
2. 微信只出现在「聊天记录」页签，快速清理页没有，用户打开软件第一眼看不到。
3. `chatdata._discover()` 漏了 `Tencent Files\nt_qq\global`（0.29 GB 没进账）。
4. 微信 4.x 的 `msg\attach` 是 `attach/<hash>/<YYYY-MM>/` 两层，`_months()` 只列一层，
   所以整个 attach 落成一行 174.7 MB，没法按月挑。
5. 接收目录根下那 96 个散落文件（1.03 GB）游离在 `Tencent Files` 之外，从来没被算进来。

## 改动

### `src\chatdata.py`

- `_discover()`：补 `Tencent Files\nt_qq\global`，作为 account=`global` 的一个根
- 新增 `_month_dirs(parent, depth=2)`：最多往下一层找 `YYYY-MM`，`_months()` 保留给单层场景
- `_wx_rows()` 的 attach 改用 `_month_dirs(depth=2)`，**按月份合并**成一行多 paths
- 新增 `fmt()` / `_cat_brief()` / `QUICK_DEFS` / `quick_groups(rows)`：把 116 行明细聚合成
  「QQ 缓存 / QQ 聊天内容 / QQ 数据库 / 微信 缓存 / 微信 聊天内容 / 微信 数据库」，
  desc 自动带「构成：图片 17.83 GB、表情 2.14 GB…」
- 新增 `_qq_homes()` / `loose_files(min_mb=50)`：由 nt_qq 反推 QQ 数据根，抓根目录散落文件
- `_row_size()` 加 `os.path.isfile` 分支：对**文件**调 `_sub_size()` 会因为 `os.scandir(file)`
  抛 `NotADirectoryError` 返回 0，导致散落文件那行被 `size > 0` 过滤掉（这个坑踩了一次）
- `CAT_ORDER` 加 `"QQ·散落": 8`

### `src\main.py`

- `VERSION` → `2.1.0`
- `_scan_worker()`：先跑 `chatdata.scan()`，结果存 `self._chat_cache`；
  快速清理页和聊天记录页共用，总耗时不变（聊天 1.4 s + 固定项 30 s）
- `_build_tab_quick(res, chat_raw=None)`：追加 `chatdata.quick_groups()` 的行，
  再按 `(level, -size)` 重排 —— QQ 缓存 22.64 GB 自动排第一
- `_build_tab_chat()`：优先用缓存；用 `self.__dict__.get("_chat_cache")` 而不是 `getattr`，
  因为 App 继承 tkinter，`getattr` 在属性不存在时会走 tkinter 的 `__getattr__` 递归爆栈
  （headless 测试时踩到 RecursionError）
- `start_scan()` 重置 `_chat_cache`，状态栏首行改「正在扫描：QQ / 微信 聊天数据…」

### `src\junk_items.py`

- 删掉 `id="qq_data"` 那条 `view` 项

## 遗留 / 注意

- 清理前建议退出 QQ、微信，否则占用中的缩略图删不掉（会跳过，不报错）
- 删缩略图后，聊天记录里图片第一次翻会重新加载，点开还是原图
